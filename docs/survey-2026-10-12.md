# Mechanism survey — 2026-10-12

本轮将目录从 **25 个项目扩展到 98 个项目**，新增 73 个；原有条目全部保留并复核。范围是有公开实现或明确设计资料的推理专用化软件及其构建工具。每条记录均有至少两个官方证据入口；关键路径采用定向代码抽查，不能视为完整代码审计或独立性能复现。

## 分类结论

模态回答“处理什么数据”，不能充分解释“为什么快、在哪里改变执行”。例如 KV 前缀复用与扩散特征复用都减少重算，但有效性条件不同；LLM 和 DiT 也都需要低比特内核、卸载与跨设备执行。因此采用 **七类执行决策 + 一类支持工具**，各项目只选一个主要浏览入口，并保留多机制标签。

| 主入口 | 本轮数量 | 核心问题 |
| --- | ---: | --- |
| 数据驻留与搬移 | 11 | 数据放在哪，计算随数据移动还是搬数据到计算端？ |
| 数值表示与低比特执行 | 9 | 如何联合设计格式、布局和计算内核？ |
| 选择性计算 | 8 | 可以省略哪些神经元、token 或注意力块？ |
| 计算复用 | 10 | 哪些旧结果还能使用，何时必须刷新？ |
| 生成顺序 | 5 | 能否一次推进多个 token 或生成块？ |
| 并行与调度 | 12 | 怎样切分阶段、设备、请求和适配器？ |
| 编译与原生执行 | 32 | 怎样降低、融合与实现具体计算图？ |
| 构建与验证工具 | 11 | 怎样生成候选程序并验证其行为和成本？ |

这些数量是编辑组织方式，既不代表机制互斥，也不代表各领域项目总量。执行类较大，内部通过 runtime、compiler、backend、kernel-library 等产物标签区分。FlashMLA 与 FlashAttention 属于特定算子的执行实现；MInference / SnapKV 则明确改变保留的计算或状态。不能因为名称里有 “sparse” 就认定它把任意稠密模型近似稀疏化。

## 对原目录和候选描述的重要修正

- **Sol-Engine：** 已定位 [Sana 的 sol-engine 分支代码](https://github.com/NVlabs/Sana/tree/sol-engine)，由 documentation-only 改为 public-code；其缓存、稀疏和精度选项仍需分别评价。
- **MetaInfer：** 更新为 [MetaInfer/MetaInfer](https://github.com/MetaInfer/MetaInfer)。固定提示词与判定器的测试不等于数值等价验证。
- **TensorFold：** 当前文档描述原生 Zig 服务运行时与模型/格式/平台资格表，旧“通用内存虚拟化”描述过时。[条目与证据](catalog.md#tensorfold)
- **KTransformers：** 以当前 kt-kernel 异构后端与服务框架集成为依据，区分 legacy 注入示例与当前路径。[条目与证据](catalog.md#ktransformers)
- **Flash-MoE：** 实读代码注明原模型 10 个活跃专家，但执行使用 K=4；不能当作相同专家配置的速度比较。[条目与证据](catalog.md#flash-moe)
- **Strata：** 特定 CUDA/HIP 配置默认启用 route-tail-skip，会跳过部分未命中专家；不能将所有路径描述成等价执行。[条目与证据](catalog.md#strata)
- **FlashMLA：** 当前分支已有破坏性模型/硬件/布局变更，旧搜索摘要中的 Hopper / 早期模型支持不能用于描述当前版本。[条目与证据](catalog.md#flashmla)
- **FastKernels：** 既包含集成评测，也有最小服务路径；其在本目录的主要角色仍是候选替换与端到端验证。[条目与证据](catalog.md#fastkernels)
- **AgentCompile：** 抽查通用 selector/verifier 发现代理计时与未实现/跳过检查，不能直接采信 README 的完整验证保证；这一结论不覆盖所有专用 family 路径。review-use 许可声明与实现成熟度分开记录。[条目与证据](catalog.md#agentcompile)
- **MFLUX：** 本轮确认的是图像接口，不因上游模型/插件名称包含 Video 就赋予 video 支持标签。[条目与证据](catalog.md#mflux)
- **仓库迁移：** PowerInfer 使用 Tiiny-AI；FlexGen 使用 FlexLLMGen；DeepCompressor 使用 nunchux-ai；MFLUX 使用 mflux-community。重定向不是新项目。

## 证据深度与未覆盖范围

所有纳入条目均检查官方说明。大多数再抽查代表源码，例如缓存触发条件、KV 分配、调度顺序、内核分派或编译入口。部分复杂系统的第二证据主要是官方使用/设计文档；Sparse VideoGen 未深入内核，OneDiff 未审计所有外部后端。闭源核心的 Halogen Flash / TensorRT 只依据公开资料或接口，AgentCompile 保留 review-use 限制。具体适用边界见各条 `caveat`。

没有安装这些引擎、下载模型或运行 GPU 实验；没有确认每个分支都可构建，没有独立验证质量/速度数字。Flash-MoE、Strata、FlashMLA 和 AgentCompile 的关键证据已固定到提交；其他分支/HEAD 链接可能随上游变化，`checked_on` 表示本次审阅日期。需要复现实验或定位缺陷时应固定版本，并按[证据政策](evidence-policy.md)记录条件。

这是一次有边界的软件调查，**不声称穷尽，也未达到系统性文献综述的收敛标准**。下一轮可优先补充：

- 量化链：GPTQ / AWQ / HQQ、QuIP# 等格式到实际部署的完整链路。
- 存储与稀疏：HOBBIT、DejaVu、mixtral-offloading；PowerInfer-2 尚未确认对应的独立官方源码，不能用同名 fork 代替。
- 基础设施：CUTLASS / CuTe、ThunderKittens、XNNPACK、TorchInductor、torch-mlir、sharktank、OpenVINO core。
- 较浅覆盖：ROCm / Ascend / NPU、手机执行路径、语音、机器人 diffusion policy、VAE 专用解码和专有硬件栈。

Ollama 类部署入口、ComfyUI 缓存插件、模型权重页面与通用 coding agent 不自动独立计数；若能证明其有不同的执行机制，可再纳入。未收录并不代表无关或质量较低。

## Mach X: integrated execution changes

1. **Dispatch reaches the kernel.** [Qwen MoE split](https://github.com/Red-Weasel/machx-inference-engine/blob/d953ea2bf88cc47e417d77931a5d2ff296726c7b/src/model/qwen35moe_split.cpp#L1234-L1256) chooses an INT8-KV path separately, otherwise calls `full_attention_fa2_decode_xmx` when the [context gate](https://github.com/Red-Weasel/machx-inference-engine/blob/d953ea2bf88cc47e417d77931a5d2ff296726c7b/src/model/q35_xmx_decode.hpp) permits it. The default threshold is 4,096 tokens and requires 16 cache rows from the current position. The kernel has additional head/group/shape gates and a SIMD fallback.
2. **Actual XMX implementation.** [attention.cpp](https://github.com/Red-Weasel/machx-inference-engine/blob/d953ea2bf88cc47e417d77931a5d2ff296726c7b/src/ops/attention.cpp#L1183-L1235) selects variants through `IE_FA2_XMX_V2`. The hd256 default's [two-subgroup body](https://github.com/Red-Weasel/machx-inference-engine/blob/d953ea2bf88cc47e417d77931a5d2ff296726c7b/src/ops/attention.cpp#L1696-L1845) uses `joint_matrix` accumulators for output, double-buffered scores, and overlap of the next block's QK work with the current softmax. This is a changed device program, not a renamed library invocation.
3. **Other execution evidence.** [Q4_K XMX GEMM](https://github.com/Red-Weasel/machx-inference-engine/blob/d953ea2bf88cc47e417d77931a5d2ff296726c7b/src/ops/gemm_q4k_xmx.cpp) dequantizes weight tiles into shared local memory and reuses them across matrix tiles. [Lane serving](https://github.com/Red-Weasel/machx-inference-engine/blob/d953ea2bf88cc47e417d77931a5d2ff296726c7b/src/engine/lanes_serve.cpp) has request-state orchestration and MTP draft submission/acceptance paths, with plain-step fallback. The [27B split](https://github.com/Red-Weasel/machx-inference-engine/blob/d953ea2bf88cc47e417d77931a5d2ff296726c7b/src/model/qwen35_split.cpp) owns per-lane MTP checkpoints. Presence of these paths does not establish sampled-distribution correctness across configurations; the 35B attention benchmark is not an MTP speedup claim.
4. **Reuse boundary.** [Third-party notices](https://github.com/Red-Weasel/machx-inference-engine/blob/d953ea2bf88cc47e417d77931a5d2ff296726c7b/THIRD_PARTY_LICENSES.md) attribute HTTP/JSON libraries and ggml-derived import/reference routines. [Build configuration](https://github.com/Red-Weasel/machx-inference-engine/blob/d953ea2bf88cc47e417d77931a5d2ff296726c7b/CMakeLists.txt) requires the SYCL toolchain; optional oneDNN paths also exist. Source comments credit llama-SYCL attention techniques. We do not repeat the README's broad “from scratch” language as a verified originality claim.

### Validation and performance boundary

- [attention_test.cpp](https://github.com/Red-Weasel/machx-inference-engine/blob/d953ea2bf88cc47e417d77931a5d2ff296726c7b/tests/unit/attention_test.cpp#L532-L640) invokes XMX and a second attention path on the same inputs. It compares against a scalar fp32 reference on fp16-rounded inputs, checks finite outputs, requires absolute reference error at most `1e-2` and SIMD difference at most `4e-3`, and poisons unused tail rows. Failures propagate to the test result. This establishes a concrete check, not a passing run performed by this catalog.
- The [v0.2.32 report](https://github.com/Red-Weasel/machx-inference-engine/blob/d953ea2bf88cc47e417d77931a5d2ff296726c7b/README.md#L186-L209) reports **62.8 → 69.8 tok/s**: 35B-A3B Q8_0, **two Arc Pro B70s**, a **32K-token prompt**, `ie-prompt-bench`, greedy decoding, prompt cache off, v0.2.31 versus v0.2.32. It reports unchanged prefill and old/new kernel byte comparisons plus finite greedy continuations. The same file distinguishes served conversational results from standalone benchmark results. [ie_attn_profile.cpp](https://github.com/Red-Weasel/machx-inference-engine/blob/d953ea2bf88cc47e417d77931a5d2ff296726c7b/tools/ie_attn_profile.cpp) provides an output-dump route for A/B checking.
- **The “same bits” claim is local to the rewrite.** The model's context gate explicitly documents fp16 probability weights, changed summation order and possible near-tie greedy flips relative to the pre-XMX path. It is incorrect to describe the complete engine as bit-equivalent to a floating-point reference, or the 27B as independently timed just because it shares the kernel. Quantization and matched MTP heads need separate contracts.
- AI participation is disclosed narrowly: a [Claude analysis](https://github.com/Red-Weasel/machx-inference-engine/blob/d953ea2bf88cc47e417d77931a5d2ff296726c7b/docs/deepseek4/79_DECODE_HOST_SYNC_PLAN_2026-09-10.md) and a [Codex adversarial review](https://github.com/Red-Weasel/machx-inference-engine/blob/d953ea2bf88cc47e417d77931a5d2ff296726c7b/docs/glm53/SERVE_SPEED_2026-10-19.md#L387-L399). These do not establish whole-engine AI authorship or reduced total development cost.

## Ignis: program reconstruction plus selective kernel replacement

1. **Explicit inherited substrate.** [Manifest](https://github.com/gpillon/ignis/blob/752103608ffeae5de1f9023a41698544fd339d8e/kernel/vendor/manifest.json) pins `gpillon/ninfer` at `a00648cb828457986cf5b4b4f712b4cbcd7af0d1`, with file hashes and patches. [NOTICE](https://github.com/gpillon/ignis/blob/752103608ffeae5de1f9023a41698544fd339d8e/kernel/NOTICE) and [README lineage](https://github.com/gpillon/ignis/blob/752103608ffeae5de1f9023a41698544fd339d8e/README.md#L594-L627) trace cometkim → natpate → Neroued. NVFP4, hyperquant KV and the base DFlash2 port are inherited work, not inventions of Ignis. The manifest's presence is not a claim that we compared every vendored byte with every ancestor.
2. **New execution/state boundary.** [Rust compute adapter](https://github.com/gpillon/ignis/blob/752103608ffeae5de1f9023a41698544fd339d8e/crates/runtime/src/cuda_leaf.rs) translates lane work into the step ABI. [decode_graph.cu](https://github.com/gpillon/ignis/blob/752103608ffeae5de1f9023a41698544fd339d8e/kernel/src/decode_graph.cu) traverses embedding/layers/head once at batch width, with device-staged lane positions and slots. [step.cu](https://github.com/gpillon/ignis/blob/752103608ffeae5de1f9023a41698544fd339d8e/kernel/src/step.cu#L2460-L2500) launches the width-specific CUDA graph or falls back to the same eager traversal. This and [KV/checkpoint scheduling contracts](https://github.com/gpillon/ignis/blob/752103608ffeae5de1f9023a41698544fd339d8e/crates/core/src/scheduler.rs) are substantive changes beyond an API wrapper.
3. **Top-k replacement is integrated.** [DFlash2 drafter](https://github.com/gpillon/ignis/blob/752103608ffeae5de1f9023a41698544fd339d8e/kernel/src/dflash2_drafter.cu#L267-L277) invokes [Ignis top-k](https://github.com/gpillon/ignis/blob/752103608ffeae5de1f9023a41698544fd339d8e/kernel/src/dflash2_topk.cu): `k=16`, vocabulary slices processed by many blocks, register-resident sorted lists and a merge pass. It retains the smaller-row tie rule and copies winning BF16 bits; unsupported k or inadequate workspace delegates to the vendored op. [Tests](https://github.com/gpillon/ignis/blob/752103608ffeae5de1f9023a41698544fd339d8e/kernel/tests/test_dflash2_topk.cu) run both operations, poison output buffers differently, compare IDs and values exactly and fail on mismatches, including ties/extremes. They do not establish complete DFlash2 equivalence.
4. **Bounded prefill workspace, with adaptation and approximation.** [GQA dispatch](https://github.com/gpillon/ignis/blob/752103608ffeae5de1f9023a41698544fd339d8e/kernel/src/gqa_layer.cu#L232-L283) sends hq prompt routes to [hq_prompt_attention.cu](https://github.com/gpillon/ignis/blob/752103608ffeae5de1f9023a41698544fd339d8e/kernel/src/hq_prompt_attention.cu), retaining other vendored routes. The header credits `mkyt/qwen3-27b-5090` at `0594e77...`; Ignis adapts this to the NInfer codec, residual-window handling and bounded bands. A default 32,768-key band avoids full-history BF16 planes. INT8 QK and FP8 PV add numerical approximation; the alternate FP16 route is not an exact-BF16 guarantee. This is a meaningful adaptation, not a wholly original attention algorithm.
5. **MoE residency is called by the model.** [Flash-Next program](https://github.com/gpillon/ignis/blob/752103608ffeae5de1f9023a41698544fd339d8e/kernel/src/flash_next/program.cu#L371-L435) calls demand residency and optional lookahead prefetch, then reads slot tables before expert compute; [residency.cu](https://github.com/gpillon/ignis/blob/752103608ffeae5de1f9023a41698544fd339d8e/kernel/src/residency.cu) implements resident/staged selection and cache policy. Low-bit expert conversion is separate from this placement mechanism; fitting a 125B model in the advertised setup is not solely a scheduler achievement.

### Validation and performance boundary

- [September A/B findings](https://github.com/gpillon/ignis/blob/752103608ffeae5de1f9023a41698544fd339d8e/docs/findings/2026-09-24-upstream-quick-wins-ab.md) report about **367 tok/s for one lane** and **1,065 tok/s aggregate at eight lanes** on one RTX 5090, Qwen3.8-27B NVFP4, hq-e8-2b KV, seven DFlash2 drafts, greedy coding prompts. The eight-lane gain in that update includes **four upstream kernel ports**, not only original Ignis changes. Reported C=1 and C=8 texts differ even when within-width before/after results match.
- [October prefill findings](https://github.com/gpillon/ignis/blob/752103608ffeae5de1f9023a41698544fd339d8e/docs/findings/2026-10-21-prefill-attention-without-prompt-planes.md) include route errors against BF16, a 16-window 4K KLD evaluation, memory accounting and same-session author benchmarks. The end-to-end A/B build also changes token-embedding placement; its full memory gain should not be assigned to attention alone. The low-precision route is assessed for error rather than claimed bit-identical.
- Both findings identify important drivers/logs under **untracked `.scratch/`** (and local dump paths). Public summaries, source tests and selected fixtures are useful evidence, but are not a complete public replay package. Cross-engine README figures use different precision/draft/context settings and sessions; no ranking is inferred.
- A grafted DFlash2 drafter, trellis/NVFP4 weights, compressed KV, YaRN extension and optional abliterated checkpoint each change the comparison contract. Draft verification is an engine mechanism; draft/model preparation is not itself an engine-only speedup. The [sampled-acceptance specification](https://github.com/gpillon/ignis/blob/752103608ffeae5de1f9023a41698544fd339d8e/docs/specs/runtime/08-dflash2-sampled-acceptance.md) distinguishes target sampling from greedy benchmarks; no general distributional-equivalence claim is made here.
- README directly discloses coding agents building parts of the engine. `ai_involvement=disclosed` does not infer autonomous construction, task shares or cost savings from an `AGENTS.md` filename.

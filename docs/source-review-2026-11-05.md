## gr8: model kernels and communication are integrated

[K1 kernels](https://github.com/kindlingai/gr8/blob/35a8f1c771991a87b0c6308006b74ce70faf0378/engine/kernels/k1.cuh) decode mixed-width trellis expert tiles and combine routed and shared experts. [The binder](https://github.com/kindlingai/gr8/blob/35a8f1c771991a87b0c6308006b74ce70faf0378/engine/kernels/bind.cuh) selects width/codebook, row shape and fused or split fc1/fc2/finalize launches. [Native S2 execution](https://github.com/kindlingai/gr8/blob/35a8f1c771991a87b0c6308006b74ce70faf0378/engine/runtime/s2/native.cuh) enqueues fabric work before captured model steps and checks fabric/attention errors; [the verbs fabric](https://github.com/kindlingai/gr8/blob/35a8f1c771991a87b0c6308006b74ce70faf0378/engine/comms/fabric.cpp) implements actual inter-rank transfers. This is execution ownership beyond a launcher or API.

[g6m4](https://github.com/kindlingai/gr8/blob/35a8f1c771991a87b0c6308006b74ce70faf0378/engine/runtime/g6m4.cu) binds optional block stores to model and draft attention caches. [KV tier code](https://github.com/kindlingai/gr8/blob/35a8f1c771991a87b0c6308006b74ce70faf0378/engine/runtime/s2/kv_tier.cuh) copies replicated and sharded page parts, orders spills before restores, and distinguishes persisted state by block format and executable stamp. This is a concrete storage/placement path, not proof that all remote-row or newer-model modes are correct.

[Credits](https://github.com/kindlingai/gr8/blob/35a8f1c771991a87b0c6308006b74ce70faf0378/CREDITS.md) explicitly identify EXL3, its ExLlamaV3 quantizer and QTIP lineage. The CUDA trellis decoder and runtime are separate contributions from the quantized release. The inspected full-GLM path is also distinct from the separately listed Spark Engine's Qwen path and libtorch-based substrate; neither name is an alias for the other. New GLM-Flash and DeepSeek source paths exist, but their complete execution/quality contracts were not reviewed here.

[The codebook test](https://github.com/kindlingai/gr8/blob/35a8f1c771991a87b0c6308006b74ce70faf0378/engine/kernels/tests/tr3_e4m3_test.cu) enumerates 16-bit/20-bit codebook states, checks fixed cross-implementation hashes and random K2–K4 tiles. [The pool-stash test](https://github.com/kindlingai/gr8/blob/35a8f1c771991a87b0c6308006b74ce70faf0378/engine/runtime/s2/tests/pool_stash_test.cpp) uses host token-row models on two ranks to check restoration, ordering and digests. It is not a hardware fabric test. Both were inspected, not executed.

[Reported benchmarks](https://github.com/kindlingai/gr8/blob/35a8f1c771991a87b0c6308006b74ce70faf0378/README.md) distinguish cold versus cached prefill and single-request versus aggregate decode. TP=3 uses approximately 2.25 bpw experts whereas TP=4–6 use 3.25 bpw, so the table is not a fixed-precision scaling experiment. The reported October 24 runs do not measure today's entire tree. Shared-step output can differ from solo output; [context-parallel batching](https://github.com/kindlingai/gr8/blob/35a8f1c771991a87b0c6308006b74ce70faf0378/engine/runtime/s2/cp_rows.h) also exposes reduction-path differences. Steering, thinking controls and experimental int4 KV require separate qualification. Some capacity figures are estimates; none is an independent measurement by this catalog.

## Basalt: separate fork delta from inherited tiering

The [README](https://github.com/jesdga95/basalt/blob/dc047a77beeddf1e91234d983a91d6bf929e9619/README.md) names Strata as its fork base. A bounded upstream comparison inspected [Strata's peer executor](https://github.com/Niko1221/Strata/blob/ffa80d73133ea5c548aefe57889a16e8085a938f/src/core/peer_experts.cpp) and [verify program](https://github.com/Niko1221/Strata/blob/ffa80d73133ea5c548aefe57889a16e8085a938f/src/core/verify.cpp): **peer GPU experts and CPU/GPU tiering already exist upstream**. Their mere presence cannot justify another record or a claim of invention.

The substantive inspected reconstruction is the [device-planned expert window](https://github.com/jesdga95/basalt/blob/dc047a77beeddf1e91234d983a91d6bf929e9619/src/core/verify/expert_execution.cpp) and [residency synchronization](https://github.com/jesdga95/basalt/blob/dc047a77beeddf1e91234d983a91d6bf929e9619/src/core/verify/expert_plan.cpp): the verifier starts peer work for an entire window, exchanges host/peer ring sequence flags and waits for the required tiers in [the combine kernel](https://github.com/jesdga95/basalt/blob/dc047a77beeddf1e91234d983a91d6bf929e9619/src/kernels/cuda/native_moe.cu). The [decode worker kernels](https://github.com/jesdga95/basalt/blob/dc047a77beeddf1e91234d983a91d6bf929e9619/src/kernels/cuda/dec_moe.cuh) supply the associated execution path. This bounded comparison establishes a meaningful different program, not a complete commit-by-commit originality audit.

[Peer prefill](https://github.com/jesdga95/basalt/blob/dc047a77beeddf1e91234d983a91d6bf929e9619/src/prefill/peer_experts.cpp) invokes grouped FP4 execution and streams bounded chunks of results through host staging. [The grouped NVFP4 implementation](https://github.com/jesdga95/basalt/blob/dc047a77beeddf1e91234d983a91d6bf929e9619/src/prefill/fp4/moe_fp4.cu) directly attributes its block-scaled MMA wrapper/tile structure to Infernix. [Third-party notices](https://github.com/jesdga95/basalt/blob/dc047a77beeddf1e91234d983a91d6bf929e9619/THIRD_PARTY_LICENSES) also identify ggml/llama.cpp formats and adapted code. NVIDIA NVFP4 experts, additional dense DQ6/DQ8 quantization and system execution are distinct contributions.

[The prefill test](https://github.com/jesdga95/basalt/blob/dc047a77beeddf1e91234d983a91d6bf929e9619/tests/cuda/prefill_fp4_test.cpp) has actual failure thresholds: gate/up relative RMS at most 1e-5 and down at most 1e-4 against a reference with the **same A4 rounding**; up to 0.2 layer-output RMS against unrounded arithmetic. It also checks grouping, edge activations and optional peer parity. These contracts validate different things and must not be collapsed into full-precision equivalence.

[The BF16 quality protocol](https://github.com/jesdga95/basalt/blob/dc047a77beeddf1e91234d983a91d6bf929e9619/docs/precision/quality.md) scores positions 256–510 after a 256-token prompt; [its implementation](https://github.com/jesdga95/basalt/blob/dc047a77beeddf1e91234d983a91d6bf929e9619/include/basalt/program/ppl_gate.hpp) omits base log-probability <= -16 terms from KL. That short gate does not exercise the >2K sparse-index selection boundary, long-context KV behavior or >=1K prompt W4A4 path. Authors provide separate longer-prompt experiments. In [the precision ablations](https://github.com/jesdga95/basalt/blob/dc047a77beeddf1e91234d983a91d6bf929e9619/docs/precision/isolated-costs.md), an interval containing zero means no detected difference at that sample size, not proof of losslessness.

[Optional route prior/tail skip](https://github.com/jesdga95/basalt/blob/dc047a77beeddf1e91234d983a91d6bf929e9619/docs/precision/routing.md) and relaxed drafting alter the routed computation or sampling distribution; the routing speed table also enables relaxed drafting and uses a different build from the quality columns. [Default thinking-loop and answer-room controls](https://github.com/jesdga95/basalt/blob/dc047a77beeddf1e91234d983a91d6bf929e9619/docs/configuration/index.md) can change generation too. [Windows documentation](https://github.com/jesdga95/basalt/blob/dc047a77beeddf1e91234d983a91d6bf929e9619/docs/platforms.md) explicitly states that no Windows quality run is available. All performance/quality measurements remain author reports.

## N3komata: a real backend patch with an approximate default

[The materializer](https://github.com/nyacom/n3komata/blob/ee0fd1182f9b045922eeb52b22dc7ac51165587d/engine/materialize.py) pins llama.cpp to `f5027fb21307eb264aed483242603d68c87b0fe3` and applies [the graph/backend patch](https://github.com/nyacom/n3komata/blob/ee0fd1182f9b045922eeb52b22dc7ac51165587d/engine/patches/llama.cpp/moe-correction.patch). Its SHA-256 matches [the published value](https://github.com/nyacom/n3komata/blob/ee0fd1182f9b045922eeb52b22dc7ac51165587d/engine/README.md): `0c535690bf1fa002132702438b436933f1cd4a8a0d72c2c7fb107f20d549b9fe`.

The patch extends existing expert-cache behavior with per-layer quotas, prefetch and batched Vulkan uploads. Router cumulative-mass masks keep fixed Kmax graph shapes, pad inactive routes and turn inactive cache slots into a -1 sentinel. Vulkan matvec shader variants check that sentinel and skip those rows. These connected graph/cache/shader changes distinguish the project from a launcher around unmodified llama.cpp. GPU slot-map lookup is a separate optional path, not enabled in the reviewed release profile.

[The default profile](https://github.com/nyacom/n3komata/blob/ee0fd1182f9b045922eeb52b22dc7ac51165587d/config/profiles/release.toml) combines Dynamic K=4..6, mass 0.60, byte-aware quotas, Vulkan-side selection, same-layer prefetch and batch-direct uploads. It intentionally omits expert contributions; IQ3_XXS is an additional approximation. The retained weights are not renormalized to reconstruct the missing computation. The OS page cache and Vulkan allocations share 16 GiB UMA; a cold expert miss still waits for SSD reads.

[The author report](https://github.com/nyacom/n3komata/blob/ee0fd1182f9b045922eeb52b22dc7ac51165587d/README.md) clearly separates experiments: quota/Dynamic-K comparisons used CPU selection and one 512-token run per speed cell; the CPU/Vulkan selector A/B used K=4..8/mass 0.80, two runs per arm and matching output hashes. Neither is the complete default release combination. The quality sample is eight documents/1,016 scored tokens; quota effects were below 1% without a consistent direction. No standalone numerical test suite or raw experiment logs were found in this pinned tree. The existing evidence supports an experimental specialized-backend case, not a verified speedup or unchanged-model claim.

## 中文结论

本轮新增 gr8、Basalt、N3komata，目录从 137 增至 **140 个项目、82 个案例**。gr8 的范围是完整 GLM-5.3 与 GB10 集群执行；Basalt 的收录依据是重构后的专家窗口与接入执行链的专用预填充，而不是把 Strata 已有的分层机制说成新发明；N3komata 有实际 Vulkan／图／缓存补丁，但默认减少专家，尚无完整默认配置的端到端基准。

各项均固定源码版本，区分量化、模型／采样改动、继承实现和作者数据。本次未运行上游构建或硬件测试。原有 137 条记录、79 个案例及其核查日期保持不变；双语简述、分类、近期收录、验证证据与生成索引同步更新。仓库整体导航／展示／维护流程的改进建议仅提供给维护者，未实施改版。
